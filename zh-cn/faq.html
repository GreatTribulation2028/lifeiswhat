10 條常見問題 · 生死記錄儀
呢頁講清楚本站記錄乜、點分類、點計數，同埋咩嘢唔會上站。
① 呢個站記錄乜？
生死記錄儀（STILL ALIVE?）記錄全球真實發生過嘅死亡新聞——唔係預測、唔係模型推算，係一條一條有出處嘅新聞記錄。內容分兩邊：分類頁 18 個新聞桶（猝死、離世與自殺、交通、火警、天災、戰爭、醫藥與疫情等），同一批新聞亦有一個 TG 死亡記錄版本（社交平台原文）。每一條都可以撳入原文連結逐字核對。站會一直記錄到 2027 年吹角節。
② 點樣分類？
分兩層。頁面層係 19 個可以撳入嘅分類格（18 個新聞檔 ＋ 中暑昏迷，後者由猝死檔篩「中暑」出嚟）。判讀層係 12 類死因：交通航空、凶案暴力、心源性猝死、意外工安、意外（非工安）、戰爭軍事、災難、疾病醫療、自殺、自然死亡、死亡統計、死因未明。一條新聞有多個線索時有 tie-break 次序：自殺 → 凶案暴力 → 戰爭軍事 → 意外工安 → 交通航空 → 災難 → 心源性猝死 → 疾病醫療 → 自然死亡 → 意外（非工安）→ 死因未明（兜底）。★ 原文冇出現嘅死因唔准推斷：只寫「猝死／猝逝」就判死因未明，唔係心源性猝死。
③ 點解同一件事最多得 2 條？
因為一宗事件通常會有幾家媒體轉發。全站設咗「同一事件上限 2 條」：用事件 id 聚組，同一組超過 2 條嘅就唔上站；URL 完全相同嘅重複亦唔會再出。目的係令數字反映「宗數」，而唔係「被轉發咗幾多次」。首頁 feed 只載最新 1,500 條做快速瀏覽，但分類桶係全量累積。
④ 「死亡統計」係乜？點計？
分三層判：① 單一具體死亡事件 → 唔算統計桶，按實際死因分類；② 死亡統計 → 主體係死亡數字／統計結果，而且有可指認嘅統計對象或出處（官方疫情統計、VAERS 死亡數、厚生勞動省嘅戰時死亡統計、研究報告嘅死亡風險等），呢類會上站；③ 框架論述／陰謀論／預測 → 死亡數字只係修辭材料，完全唔上站。實際做法係先用機械閘（統計術語，或「死亡＋數字＋累計／排行」）篩出候選，再逐條語意判讀。回測結果：統計桶召回 100%、機械判桶嘅真確率 91.7%。
⑤ 疫情／疫苗死亡點解要特別小心？
因為呢類最容易被講成陰謀論，但當中有一大部分其實係官方統計數據本身（CDC、VAERS、各國衛生部門、DSMB、具名研究者嘅估算）。準則分得清清楚楚：主體係研究或官方統計（例：「輝瑞文件：推出後三個月 1,223 人死亡」）→ 當死亡統計上站；主體係某人／某機構嘅主張、呼籲或陰謀論（例：「醫院方案同疫苗殺死咗百萬美國人」）→ 唔上站。所以「醫藥與疫情」呢個桶入面有真統計，但唔會收陰謀論。
⑥ 「三層摺疊」係咩？
時間軸頁（七年大災難 2019–2028）用三欄：左欄係印璽時間軸 TRIBULATION TIMELINE，每格一宗事件對應返現實新聞；中欄同右欄係聖經·大災難·資訊（經文、預言出處同資源連結）。每一格事件下面仲可以撳開「ACCESS SYSTEM DATA」摺疊層，睇到日期、出處同觀察記錄。分類頁每個桶亦有「統計表」摺疊，撳開可以睇月份走勢同子清單分佈。
⑦ 資料來源同更新頻率？
新聞資料每日行一次閉環：收集 → 分類 → 去重 → 語意判讀 → 瘦身 → 地震資料 → 三語生成 → 上載 GitHub Pages，上載後一兩分鐘生效。分類桶係全量累積；首頁 feed 只係最新 1,500 條。地震頁嘅資料直接來自美國地質調查局（USGS）官方實時資料庫，頁面讀同一個 data_eq.js，離線亦打得開。
⑧ 「突然死亡」嘅定義？
分兩層：分類頁嘅「猝死」桶係新聞分類（標題或內文屬突然離世嘅新聞）；判讀層嘅「心源性猝死」就要求原文有明確線索（心臟驟停／心梗／心臟病發／腦溢血）。只寫「猝死／猝逝／突然離世」而冇講明死因 → 判「死因未明」。另外「中暑昏迷」冇獨立資料檔，係由猝死檔篩「中暑」出嚟，數字自然會細好多。
⑨ 咩係未證實、唔會上站？
以下一律唔上站：研究／政策倡議而冇具體死亡事件（但官方死亡統計算數）、陰謀論同預言、動物死亡、歷史舊案同悼念文、淨係提到「死亡」但冇具體事件、廣告宣傳、比喻（例如「政策會殺死經濟」）、未死或未確認死（搶救中／輕生未遂／復活）。網傳新聞要有具體人名／地點／日期 ＋ 具體死因先收得，淨係一個「網傳」唔收；框架論述（有死亡數字但刪走死亡字眼後剩唔低可指認嘅統計對象）一樣唔上站。
⑩ 點樣舉報錯漏？
每條記錄都保留返原文連結，可以直接對住原文核對。如果發現錯漏，歡迎喺 GitHub 公開 repo（GreatTribulation2028/lifeiswhat）開 issue，或者直接向站主反映，會逐條覆核。本站改任何嘢之前一定先備份，所以錯漏可以回溯修正，唔會「改咗就冇」。
